## Bugs Encontrados

### Bug 1 — Code sem validação FluentValidation (Create)
- **Severidade:** Média
- **Localização:** CreateAcquisitionSourceTypeValidator.cs (Domain) e CreateAcquisitionSourceTypeRouteValidator.cs (Api)
- **Descrição:** Nem o validador de domínio nem o validador de rota validam a propriedade Code. O CreateAcquisitionSourceTypeRequest expõe Code como string? (nullable). Se o utilizador enviar um payload sem Code, a validação passa e o erro só surge ao nível da DB (constraint violation), resultando numa má experiência de utilizador.
- **Esperado:** O validador deve ter RuleFor(x => x.Code).NotEmpty().MaximumLength(50).
- **Atual:** Nenhuma regra de validação para Code.

### Bug 2 — Sem verificação de unicidade de Code no AppService
- **Severidade:** Baixa
- **Localização:** AcquisitionSourceTypeAppService.CreateAsync()
- **Descrição:** O método CreateAsync verifica unicidade do Name (ExistsByNameAsync) mas não do Code. A DB tem unique index UQ_AcquisitionSourceTypes_Code que rejeitará duplicados, mas sem feedback amigável ao utilizador.
- **Esperado:** Verificar ExistsByCodeAsync antes de criar.
- **Atual:** Apenas verifica Name duplicado.
